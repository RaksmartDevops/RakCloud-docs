# 响应结构

API 通过 **HTTP 状态码** 表示请求结果，通过 **JSON 响应体** 返回数据或错误信息。请优先根据状态码判断请求是否成功。

## 成功响应

### 200 OK

查询类接口成功时返回 `200`，响应体为资源数据。

单个资源：

```json
{
  "service": { "id": 12345, "hostname": "web-01", "domainstatus": "Active" },
  "hostname": "web-01",
  "cpu": 2,
  "memory": 4096
}
```

资源列表：

```json
{
  "count": 12,
  "offset": 0,
  "limit": 10,
  "services": [ { "id": 12345 }, { "id": 12346 } ]
}
```

列表结构说明请参见 [分页](./pagination.md)。

### 204 No Content

操作类接口（如开机、关机、挂载）成功时返回 `204`，**没有响应体**。

`204` 表示操作指令已被受理并下发，不代表操作已经执行完成。如何确认操作结果，请参见 [异步操作](./async-operations.md)。

## 错误响应

请求失败时，API 返回 `4xx` 或 `5xx` 状态码，响应体格式统一为：

```json
{
  "error_message": "service is suspended"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `error_message` | string | 错误描述，供排查参考 |

::: tip 提示
`error_message` 的内容用于帮助理解错误原因，可能随版本调整。请在程序中根据 **HTTP 状态码** 进行判断和处理，不要依赖 `error_message` 的具体文字。
:::

各状态码的含义请参见 [HTTP 状态码](./status-codes.md)。

## 响应头

| 响应头 | 说明 |
| --- | --- |
| `Content-Type` | `application/json; charset=utf-8` |
| `X-Request-Id` | 本次请求的唯一标识 |

### X-Request-Id

除 `429` 外，API 的每个响应都包含 `X-Request-Id` 响应头，例如：

```
X-Request-Id: 2e77f33e-ab2a-4507-84a1-b483982c6303
```

建议在您的日志中记录该值。提交工单反馈问题时，请提供 `X-Request-Id`，以便快速定位请求。

使用 curl 查看响应头：

```bash
curl -i https://rak-api.raksmart.com/rakapi/v2/user \
  -H "X-API-Key: $RAKSMART_API_KEY"
```
